# First-build measurement protocol

Status: passed on 2026-09-07. The full build and packaging completed before the
build workflow was added. Raw evidence is in measurements/T1-2026-09-07.

## Required input evidence

1. Identify the Linux x86_64 builder and its available CPU, RAM, disk, SDKs,
   build tools, and connected Android devices.
2. Select a real Flutter stable tag and record its engine.version and engine.stamp.
   Do not infer supported versions from example manifests or historical notes.
3. Inspect the prototype engine diff. Recover only the E8 factory allocation
   finalization fix into a local patch; exclude temporary diagnostics and other
   toolchain changes. Check its applicability against the exact selected source.
4. Record and pin the actual depot_tools commit. Disable its automatic update.
5. Synchronize the reviewed local repository commit to a dedicated builder
   checkout. Keep experimental server directories read-only as references.

## Manual build

Run SPEC_M1 WP-1 steps 1-8, retaining complete stdout/stderr and exit status.

- Resolve the Flutter tag, verify a 40-digit engine commit, and check it out.
- Run gclient sync -D --no-history with pinned depot_tools.
- Check HEAD equals the requested commit; check and apply the local patch.
- Generate Android arm64 release with --no-prebuilt-dart-sdk and
  --dart-dynamic-modules; verify dart_dynamic_modules = true in args.gn.
- Inspect gn ls to determine the targets producing libflutter.so, embedding,
  and clang_x64/gen_snapshot. Build only those targets, not all of host_release.
- Verify the actual locations and ELF host/target architectures. Run
  gen_snapshot --version. Identify whether the release engine is stripped.
- Package using the selected engine stamp's Maven coordinates. Preserve the
  embedding bytes; record SHA-256 hashes and the same build ID for the pair.

Measure initial synchronization separately from warm synchronization. If an
existing dependency cache is reused, label the result warm and leave the cold
measurement TBD. Record the memory measurement method and parallel job count;
do not label a single child's RSS as the entire build's peak memory.

## Stop conditions

Stop and report failed source, patch, GN, or artifact assertions. Do not use
force, three-way patch application, or a fallback build configuration. Do not
copy prototype binaries into the output to make missing targets pass.
